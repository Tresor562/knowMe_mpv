# KMD-355 — Pin canonical CI runner release family

## Status

Active delivery candidate. Merge only after exact-head CI is green and review/thread gates are clear.

## Goal

Reduce unbounded CI environment drift by replacing the moving `ubuntu-latest` GitHub-hosted runner label with the explicit `ubuntu-24.04` release family for the canonical `quality` job.

This does not make the hosted runner image byte-for-byte immutable. GitHub continues to patch the `ubuntu-24.04` image. The purpose of this delivery is narrower: prevent an automatic future major Ubuntu runner-family transition from changing KnowMe CI semantics without a repository change and review.

## Changes

- `.github/workflows/ci.yml`
  - canonical `quality` job now uses `runs-on: ubuntu-24.04`;
  - all previously pinned actions, Node runtime and PostgreSQL service digest remain unchanged.
- `scripts/ci-workflow-supply-chain-preflight.test.mjs`
  - requires the explicit `ubuntu-24.04` runner family;
  - rejects regression to `ubuntu-latest`;
  - preserves all existing action, runtime and image pinning checks.

## Validation required before merge

1. Supply-chain preflight passes on the exact PR head.
2. Dependency installation succeeds on `ubuntu-24.04`.
3. Prisma generation and committed migration validation pass.
4. Full monorepo build and unit/test suite pass.
5. Web Playwright E2E passes.
6. API PostgreSQL-backed E2E passes.
7. No unresolved review thread or merge conflict exists.

## Migration

No Prisma, user-data, API-contract or application-state migration is introduced.

## Rollback

Revert the KMD-355 merge commit to restore the previous runner label. Do not silently change to another runner family: any future runner-family change should be reviewed with the same exact-head CI gates.

## Proof boundary

This delivery proves repository configuration and CI compatibility with the `ubuntu-24.04` runner family only after GitHub Actions executes successfully on the exact head. It does not prove a byte-identical runner image, physical-device behavior, production deployment, legal/privacy approval, backup restoration, monitoring delivery, or store publication.

## Known remaining reproducibility gap

The repository still has no committed `pnpm-lock.yaml` and installation still uses `--frozen-lockfile=false`. KMD-355 does not claim to solve dependency-resolution reproducibility. A canonical lockfile must be generated by the exact configured PNPM toolchain and validated before frozen installation can be enforced.
